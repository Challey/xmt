# 短闻 · 节奏信流（Rhythm Feed）

路径：`/read`。产品名：**短闻**。

## 新范式：不是「短视频的文字版」

| | 短视频信息流 | **节奏信流（短闻）** |
|--|--------------|----------------------|
| 单位 | 一条视频 | **一则可信摘要（核）** |
| 驱动力 | 算法推荐 + 不确定奖励 | **可信 + 今日节奏** |
| 连读 | 无限下滑 | **可连读，但有呼吸点** |
| 停顿 | 被设计为「很难停」 | **「够了」一等公民** |
| 完成感 | 永远差一条 | **今日软目标 / 今日页收尾** |
| 信任 | 弱 | **徽章 · 溯源 · 原文** |

一句话：**像刷短视频一样顺手连读；像读报一样随时可以停。**

### 为什么这样设计

1. **人性**：快速获取「发生了什么」需要的是 **核（核心摘要）**，不是标题党或完整长文。  
2. **粘性**：竖滑一屏一条，降低决策成本，形成节奏。  
3. **反沉迷**：用 **呼吸点**（每约 7 则）、**今日软上限**（约 18 则提示一次）、**会话时长提示**（约 12 分钟）和顶栏 **「够了」**，把「停」做成体面出口，而不是道德说教或硬锁。  
4. **可信**：每则保留信任徽章与原文入口；摘要应来自原文提炼（见 `ShortSummaryGenerator`）。

## 信息结构：核先于题

每张卡片：

1. **核**（主读）— `card.brief`，大字号摘要  
2. **题**（锚点）— 标题缩小为次要定位  
3. **要点**（可选）— 2～5 条  
4. **动作** — 原文 / 详情 / 复制摘要 / 稍后  

信流默认 `/read`；速览 `?mode=browse`。

## 节奏机制（客户端）

| 机制 | 行为 |
|------|------|
| 呼吸点 | 本段连读每 7 则，轻浮层：继续读 / 看今日 / 先这样 |
| 今日软目标 | 约 18 则后提示「今日节奏差不多了」（不强制） |
| 会话提示 | 本段约 12 分钟后结合呼吸点提示 |
| 够了 | 顶栏按钮，主动打开停顿文案 |
| 今日进度条 | 可视化当日读量相对软目标 |

实现：`js/short-read-rhythm.js` + `css/short-read-pulse.css`。

## 模式与入口

| 模式 | URL | 说明 |
|------|-----|------|
| 信流 | `/read` | 竖滑连读，默认 |
| 速览 | `/read?mode=browse` | 列表扫核 |
| 详情 | `/read/{nid}` | 摘要 → 要点 → 正文线索 → 原文 |
| 今日 | `/read/today` | 收尾与回顾 |
| 稍后 | `/read/later` | 延后而不消失 |

筛选：信任 `?level=`、领域 `?domain=`（见 [domains.md](domains.md)）。

## 视觉

- 白天 / 黑夜 token（`xmt_duanwen_theme`）  
- Apple 精修层 + Pulse 层：核大、题小、玻璃顶栏、呼吸点卡片  
- 左侧信任轨：提醒「可核验」

## 验收

1. 信流中 **3 秒内读完核**，标题不抢戏  
2. 上滑可连续 ≥7 则后出现呼吸点，可选继续  
3. 「够了」可一键去今日，无内疚文案堆砌  
4. 徽章与原文始终可达  
5. 不依赖无限推荐算法制造焦虑
